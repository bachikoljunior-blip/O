# Agent instructions

1. Treat `.continual/runs/`, `.continual/episodes/`, `.continual/candidates/`, and evidence ledgers as persistent truth; chat history is not the source of truth.
2. Keep semantic judgment in active prompts or scoped Candidates, not fixed Python branches.
3. Evaluate a Candidate immediately before the exact component it can affect; never activate a new Candidate globally at creation time.
4. Preserve supporting and contradictory evidence. Active-for-scope is reversible.
5. Perform Local Learn at the end of every semantic execution except Learn itself. Keep Post-task Learn.
6. Do not store hidden chain-of-thought. Persist objectives, actions, important decisions, observations, evidence, failures, unknowns, and reusable findings.
7. Use invocation journals and idempotency records. Do not repeat an external side effect merely because a process restarted.
8. Never read, write, log, or commit secrets. Model subprocesses receive a sanitized environment.
9. Active prompts/system pointers/workflows are protected from direct model edits; propose a Candidate.
10. `NO_CHANGE`, negative benchmark evidence, and `UNCERTAIN` are valid results.
11. Do not claim AGI from architecture, self-report, a task-specific reference agent, or a narrow benchmark. Use `src/agi/evaluation.py` and preserve unmet criteria.
12. A checkpoint is not task abandonment. Resume or create a persisted continuation when the objective remains unmet.
13. For Work-mode development or its scheduled recovery, read `agi/WORK_MODE.md`, `agi/WORK_MODE_HANDOFF.json`, `agi/WORK_MODE_MONITOR.json`, `agi/WORK_EXECUTION_STATE.json`, `agi/WORK_STRATEGY.json`, `agi/USER_REQUEST_QUEUE.json`, `agi/REPORTING_TARGET.json`, `agi/CONTINUATION.json`, and `agi/AUTONOMY_STATE.json` before selecting or executing work. `agi/STANDALONE_HOURLY_AUTOMATION.md` and `agi/HOURLY_EXECUTION_STATE.json` are legacy Chat-mode records after the Work migration is present.
14. In watchdog mode, the model actually running in the automation/task chat is the primary reasoning and implementation agent. The repository contains the unfinished AGI architecture, tools, learned skills, Candidates, Episodes, evidence, objective, and durable memory; it is not a separate model that replaces the session's reasoning.
15. The same task chat may be reused across watchdog recoveries, but every recovery must perform a logical context reset. Prior chat messages, prior final answers, hidden reasoning, unsaved plans, and unpersisted tool results must not be used as work state. Repository latest `main` is the only continuation source.
16. Use `agi/WORK_EXECUTION_STATE.json` as the authoritative single-execution lease after the Work migration is present; use `agi/HOURLY_EXECUTION_STATE.json` only as legacy history. Never run two executions concurrently. The scheduled trigger is a watchdog only: if a recent running Work heartbeat or verified current-session liveness exists, do not mutate the repository; if the Work lease is stale, released, interrupted, or checkpointed while the AGI objective is still unmet, recover from latest `main` only after fenced compare-and-swap authorization and remote readback. Scheduled boundaries are audit fields only and must not terminate an active execution.
17. Prefer the highest-performance model available to the automation, but do not block AGI development solely because the actual model is not GPT-5.6 Pro. Record `required_model`, `actual_model`, whether the actual model was platform-verified, and the verification source. Never claim a model identity that cannot be externally verified.
18. The primary destination for every watchdog recovery report is the same automation/task chat. Reporting must not turn prior chat history into continuation state; only repository latest `main` may provide durable continuation.
19. If direct report delivery is unavailable, persist the complete factual report under `agi/reports/` and update `agi/LATEST_HOURLY_REPORT.json` before releasing or checkpointing the lease. Never claim delivery without platform confirmation.
20. Every report must include trigger time, watchdog/lease decision, model verification state, completed changes, PRs and SHAs, successful and failed validation, unmerged or blocked work, exact next action, and truthful AGI claim boundary. This is required even when the watchdog does no work because another healthy execution is already active.
21. Do not voluntarily finalize merely because an hour elapsed, a report can be written, a commit/PR/merge completed, CI is pending, or one milestone finished. If the platform/process is about to end, safely finish or leave unmerged any in-flight mutation, inspect latest main and final CI/PR state, persist exact continuation and evidence, and leave a stale-detectable or released lease as appropriate so a later watchdog can recover without rediscovery. If verified AGI is genuinely established by the strict external gate, persist the evidence and completed state before ending.
22. User-visible reports must summarize evidence and decisions without revealing hidden chain-of-thought, and must not relabel intermediate progress as AGI.
23. Treat development of O itself as an O execution and learning target. Use `src/continual/self_application.py` and `agi/SELF_APPLICATION.md` to persist task-chat outcomes as native Run, Episode, optional inactive scoped Candidate, invocation journal, and internal evidence before a logical reset, checkpoint, or process end.
24. Physical fresh context is not mandatory for ordinary development without contamination signals. If context accumulation, stale state, duplicate exploration, or evaluation contamination is suspected, persist to latest main and logically reset. Use fresh execution for retention and transfer validation, and fresh independent execution for independent evaluation. Never mark a PASS unless the selected boundary was actually satisfied.
25. Self-application evidence is always internal development evidence and is inadmissible for the strict external AGI claim gate. A new execution environment or same-model fresh component may replace the current path only after a scoped comparison shows lower expected completion time without protected regressions; preserve rollback and negative evidence.
26. Work-mode development uses `continual work-start`, `work-pending`, `work-submit`, and `work-resume` so the current Work model drives the ordinary O Engine semantic components through immutable request and response records. An unverified platform model identity must remain explicitly unverified.
27. The primary Work execution does not voluntarily finalize while the strict external goal remains unmet and safe executable work exists. After each unit it selects the next falsifiable unit. If the platform forces the run to end, persist the exact native O continuation and leave the Work lease interrupted or checkpointed so the watchdog can recover it.
28. The Work watchdog is insurance, not the normal developer. Recovery eligibility never grants mutation authority. A recovery writer exists only after an exact generation-plus-one state-only compare-and-swap, a new execution id and fence, predecessor and old-blob binding, and a second state-only remote readback that matches the acquired lease.
29. Minimize defensible expected elapsed time to real-world AGI under the unchanged strict independent external production evidence gate. O is an instrumental, replaceable implementation path rather than the goal: compare, change, replace, or abandon it when retained evidence favors another safe route. Prefer held-out, mechanically judged, and independent external evidence; detect saturation and exploration bias and search materially different methods or information. Never defer indefinitely: persist the observed reason, selected alternative, finite reevaluation condition, and latest reevaluation time. This optimization policy is itself falsifiable and may not weaken the gate, evidence integrity, or single-writer safety.
30. Persist important ambiguities, proposals, and user-only environment, permission, operation, or information needs in `agi/USER_REQUEST_QUEUE.json`. Never store secrets in that queue. Every open request is non-blocking at project scope and includes safe reversible alternative work plus a finite reevaluation condition. Waiting for the user is not a primary-run exit condition.
31. `agi/USER_INPUT_INBOX.json` on latest remote `main` is the append-only out-of-band user-input control plane. At every safe Root or logical-unit boundary, compare its revision with the highest revision already acknowledged in durable execution state and ingest any newer active entries without requiring watchdog recovery. Reading the control inbox is not a development-writer mutation and must not create a second writer.
32. User-input inbox entries are directions, constraints, design context, or hypotheses, not automatic technical truth or AGI evidence. Preserve the terminal objective and explicit user constraints, but test technical proposals and reject or revise them when evidence favors a better route. Persist the highest acknowledged inbox revision and enough factual interpretation to survive context reset.
33. Skill-in-Skill user design context means recursive situation-dependent context routing, not merely fixed-depth composition: a Skill may expose multiple child Skills; select one or more relevant children for the current situation, recurse through their children to arbitrary useful depth, and materialize only the selected contextual branches.
