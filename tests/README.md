# tests/ — 直す前に測るための道具

このゲームは区切りのない改善ループで作られています。ここにあるのは、その各周で
**手を入れる前に現状を数字にする**ための計測です。合否を見るためだけのものではありません。

```
npm test                すべて順に回す
npm test -- 天候        名前か説明に「天候」を含むものだけ
npm test -- --list      一覧
node tests/wx2.mjs      1 本だけ
```

サーバは各テストが空きポートに自前で立てます。事前に何か起動する必要はありません。

## 守ること

**並列にしない。** SwiftShader を同時に何本も立てると偽の失敗が出ます。実際に
12 件出したことがあり、1 本ずつ回せば 25/25 通りました。`run.mjs` は順に回します。

**数値は `window.__game` から取る。** SwiftShader 越しだと 2fps 程度しか出ないので、
`requestAnimationFrame` を待つ計測や、2 枚のスクリーンショットの差を見る計測は、
それだけで壊れます（天候と時刻が撮影の間に変わる）。

**`errs` を見る。** ページ内の例外は `report(errs)` が出します。第32周に、
採取物の色を書き忘れていたせいで描画が毎フレーム例外で中断し、それ以降に積まれる
はずのアクター・旅人・鳥がまるごと出ていなかったのが、これで見つかりました。
画面は「敵がいないだけ」に見えるので、絵を見ていても気づけません。

## 測定でつまずいた型

同じ穴に落ちないよう、実際にやった取り違えを残しておきます。

| やったこと | 何が起きたか |
|---|---|
| `g.updateNPCs?.(dt)` を呼んだ | そんなメソッドは無い。`?.` が黙って何もせず「NPC は動かない」と誤診した |
| 二分探索で回避の猶予を求めた | 回避は閾値でなく**窓**。早すぎる転がりも無敵が切れて当たる |
| 連携の次撃まで数えた | 「どう転がっても避けられない技が2種」と出たが、実際は0種 |
| 乱数を固定して AI を回した | 毎フレーム同じ判断をして距離を詰め、窓が 0.05 秒に見えた。実戦の揺れを残して過半で判定する |
| 平地のつもりで 10m 歩かせた | 平地ではなかった。`flatGround()` を使う |
| 画面の平均輝度で発光を測った | ACES が高輝度を圧縮するので差が出ない。明るい画素の数を数える |
| `opts.source` を渡さず `impact()` を呼んだ | 早期 return する仕様。テストが無反応に見えた |

## ハーネス

`harness.mjs` に共通部分があります。

- `open({ width, height, audio, start })` — サーバを立ててブラウザを開き、旅を始めるまで進める
- `ok(label, cond, extra)` — 判定。`  OK  ` / `  FAIL` で始まる行を出す（`run.mjs` が数える）
- `report(errs)` — 最後に呼ぶ。落ちていれば終了コードを 1 にする
- `flatGround(page)` — 平らな地面へ移す
- `median(list)`

## 測定だけのもの

`balance`（難度の掃引）・`gang2`（囲まれたとき）・`bench`（地形の速度）は判定を持ちません。
数字を出すだけです。合否ではなく、前の周と比べるために回します。
