# loop/ — 周回のあいだ、覚えていられないことを置く場所

このゲームは区切りのない改善ループで作られています。回しているセッションは永遠には
続きません。文脈が伸びれば要約されて薄れますし、落ちることもあります。そのとき失われる
のはコードではなく**判断の理由**です。何を目指していたのか、何を試して駄目だったのか、
次に何をするつもりだったのか。

ここにあるのは、それを持たせるための**器だけ**です。中身は回す側が決めます。

| ファイル | 何が書いてあるか | 誰が変えるか |
|---|---|---|
| [`GOAL.md`](GOAL.md) | 依頼者からの指示そのまま | 誰も変えない |
| [`state.json`](state.json) | 基準・次の一手・駄目だったこと・ロック・申し送り | 回す側が毎周 |

## 1周のやりかた

1. `GOAL.md` と `state.json` を読む。特に `handoff` と `tried`
2. `lock.startedAt` が45分以内なら、別のセッションが作業中。**何もせず終わる**
3. `lock` を自分のものにして push
4. やる
5. commit / push
6. `state.json` を更新して `lock` を外す
7. 時間があれば 4 に戻る

**4で何をやるかは、あなたが決めます。** `backlog` に前の周が書き残していればそれを、
無ければ自分で決めてください。決めた理由を `backlog` や `handoff` に残しておくと、
次の周が同じ検討をやり直さずに済みます。

## criteria について

`GOAL.md` にあるのは「以上のタイトルに劣らないクオリティで」だけです。**それが具体的に
何を指すかは書かれていません。** 決めるのはあなたです。

決めたら `criteria` に書いてください。書かないと、周回ごとに解釈がぶれます。ぶれた
まま何十周も回すと、方向の違う改善が積み重なって、どこにも寄っていきません。

一度書いた `criteria` は、間違っていたと思えば書き換えて構いません。固定なのは
`GOAL.md` の文面だけで、その解釈ではありません。ただし書き換えたなら、なぜそう
判断したかを `handoff` に残してください。

## lock について

45分で失効します。1周が15〜25分なので、その2倍弱です。落ちたセッションのロックが
残り続けると、ループが二度と動かなくなります。

作業が45分を超えそうなら、途中でも `lock.startedAt` を打ち直してください。
